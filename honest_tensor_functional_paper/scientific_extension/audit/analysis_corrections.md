# Analysis corrections

The first summary pass attached the tensor procedure's interval widths/coverage to every scalar row, including the direct baseline. Before reporting results, the direct row was corrected to its own Gaussian interval using its saved direct errors. Scalar MSEs and all data draws were unchanged. The generator now computes the direct interval correctly. Other scalar variants share the proposed interval and differ only in their scalar estimate; the “legacy direct fallback” is an ablation on the new pilot calibration, not a rerun of the old R1 method. The only finite-check execution error was a Python 3.9 incompatibility (`int.bit_count`); replacing it with binary-string counting allowed all checks to run.

A larger runtime study triggered divide/overflow/invalid warnings in NumPy's matrix multiplication on bounded SVD-projector factors. The TT implementation now raises on these signals, recomputes the product using direct einsum summation, and rejects any nonfinite result. A forced-fallback regression check compares it with the independent contraction, and a nonfinite-input check confirms explicit rejection. Because this changes the numerical execution path, the entire new-stage reproduction pipeline was rerun, including all affected TT experiments and report artifacts. These reruns replace results of the same registered draws; they are not added to the 109,000 unique Monte Carlo data-set count.

The full reproduction also exposed the same bounded-product warning in the synthetic TT loading generator, outside the public API. Those products now use the checked routine as well, with explicit unit-loading and core-alignment assertions. The five affected follow-up configurations and their downstream summaries were rerun afterward. No nonfinite numerical result was retained.

The independent finite-check projector oracle also encountered this backend FP flag despite finite, identity-consistent outputs. Its matrix products were changed to direct einsum summation, keeping the oracle independent of the production checked-BLAS path. The same 40,553 checks were rerun and pass; this changes neither the mathematical checks nor simulated observations.
