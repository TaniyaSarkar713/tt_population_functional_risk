Work on the review
Assume you are a senior researcher in statistics, machine learning, theoretical computer science, and scientific writing, with experience revising papers for journals such as JASA, Annals of Statistics, JRSS-B, Biometrika, Bernoulli, NeurIPS, ICML, and COLT.
A complete scientific review of this paper has already been conducted.
Your task now is to work through that review systematically and revise the research project and manuscript until all scientifically important concerns have been resolved as far as possible.
Do not merely summarize the review.
Do not simply rewrite sentences to make criticisms disappear.
For each review comment, determine whether the underlying issue requires:
new theory;
corrected theory;
additional proof;
weaker assumptions;
a revised theorem;
a counterexample;
new simulations;
additional robustness experiments;
stronger baselines;
revised real-data analysis;
improved interpretation;
restructuring;
rewriting;
clarification;
or no change because the criticism is not technically valid.
Review all relevant files in the project folder, including:
manuscript;
appendix;
theorem statements;
proofs;
simulation code;
simulation results;
real-data analysis;
figures;
tables;
literature review;
prior novelty assessment;
full scientific review;
referee-style reports;
revision recommendations.
The objective is to convert the review into a concrete, scientifically rigorous revision of the paper.

1. Read the entire review before modifying the paper
First reconstruct all issues identified in the review.
Do not start editing after reading only the first few comments.
Create a complete issue registry.
For each issue record:
| ID | Review concern | Severity | Paper location | Scientific type | Proposed action | Status |
|---|---|---|---|---|---|
Use severity levels:
P0 — Critical
Potentially affects:
correctness;
validity;
identifiability;
novelty;
main theorem;
main empirical conclusion.
P1 — Major
Could plausibly lead to rejection or major revision.
P2 — Moderate
Meaningful improvement but does not threaten the core paper.
P3 — Minor
Presentation, notation, organization, or polish.
Work in the order:
P0→P1→P2→P3.P0 \rightarrow P1 \rightarrow P2 \rightarrow P3.
2. Separate scientific problems from presentation problems
For every review comment classify it as one of:
THEORY
The mathematical result, assumptions, rate, proof, or interpretation is problematic.
METHOD
The estimator/procedure is unclear, incomplete, or theoretically unsupported.
SIMULATION
The empirical design does not adequately test the theory.
REAL DATA
The application, preprocessing, dependence structure, or interpretation is weak.
NOVELTY
The contribution is insufficiently distinguished from prior work.
WRITING
The result may be correct but is explained poorly.
REPRODUCIBILITY
Important implementation details are missing.
NOTATION / STRUCTURE
Presentation problem.
This classification should determine what type of revision is required.

3. Resolve correctness issues before strengthening the paper
If the review identifies any possible mathematical error, address it first.
Do not proceed by merely modifying the exposition.
For example, if the paper claims
∥θ^−θ⋆∥=Op(rn),\|\widehat\theta-\theta^\star\| = O_p(r_n),
verify the proof independently.
If the proof only establishes
Op(rn′),rn′>rn,O_p(r'_n), \qquad r'_n>r_n,
then either:
prove the stronger result rigorously; or
revise the theorem and all downstream claims to the correct rate.
Never preserve a stronger theorem merely because it makes the paper more attractive.

4. Revisit identifiability when flagged
If the review raises an identifiability problem, address it mathematically.
Determine whether
Pθ1=Pθ2P_{\theta_1} = P_{\theta_2}
can occur for
θ1≠θ2.\theta_1\neq\theta_2.
If the model is identifiable only up to an equivalence relation
θ1∼θ2,\theta_1\sim\theta_2,
redefine the estimand and loss accordingly.
Examples include invariance to:
sign;
permutation;
rotation;
scaling;
factorization.
Do not continue proving consistency for a parameter that is not uniquely identifiable.

5. Work through every theorem-related criticism
For each theorem concern, reconstruct:
Assumptions→Lemmas→Main Result.\text{Assumptions} \rightarrow \text{Lemmas} \rightarrow \text{Main Result}.
Determine exactly where the problem occurs.
Possible actions include:
Strengthen the proof
Fill a missing argument.
Add a lemma
If an intermediate result is required.
Strengthen assumptions
Only when mathematically necessary.
Weaken assumptions
If the review correctly identifies unnecessary restrictions.
Revise the theorem
If the originally claimed result is too strong.
Add a lower bound
If optimality is claimed without justification.
Add an impossibility result
If an important boundary of the method can be characterized.
Add a special-case theorem
If the general result is too opaque.
Do not patch a proof locally without checking whether the change propagates to later results.

6. Maintain theorem status labels
While revising, label each theoretical result internally as:
PROVED
Complete proof verified.
REVISED AND PROVED
Original theorem changed and new version verified.
PARTIAL
Some technical step remains unresolved.
CONJECTURED
Plausible but unproved.
Only PROVED and REVISED AND PROVED results may appear as formal theorems in the final manuscript.

7. Address restrictive assumptions seriously
If reviewers criticize assumptions, do not respond only with:
“This assumption is standard.”
Investigate whether it can be weakened.
For every important assumption AjA_j, consider whether the theorem still holds under
Aj′⊃Aj.A_j' \supset A_j.
Determine which proof step fails when AjA_j is weakened.
If the assumption cannot reasonably be removed:
explain precisely why it is needed;
provide interpretation;
compare it with assumptions in the closest literature;
discuss its practical implications;
examine the consequences when the assumption fails in simulations.

8. Address rate and optimality concerns
If reviewers question a convergence rate, compare carefully with known theory.
Suppose our result is
rnoursr_n^{\text{ours}}
and existing work achieves
rnexisting.r_n^{\text{existing}}.
Determine whether the difference comes from:
stronger assumptions;
weaker assumptions;
different loss;
different parameter space;
contamination;
dependence;
dimension;
computational restrictions.
Avoid misleading comparisons.
If the rate appears suboptimal, determine whether:
the proof is loose,
the estimator is suboptimal,
or
the problem itself requires the slower rate.
If possible, derive or investigate a minimax lower bound.

9. Address novelty concerns through mathematics
If the review says the contribution appears incremental, do not simply strengthen the wording.
Re-examine:
Existing theory⟶Our theory.\text{Existing theory} \quad\longrightarrow\quad \text{Our theory}.
Make explicit what changes mathematically.
Examples:
i.i.d.→dependent observations,\text{i.i.d.} \rightarrow \text{dependent observations}, sub-Gaussian→ϵ-contamination,\text{sub-Gaussian} \rightarrow \epsilon\text{-contamination}, estimation→valid inference,\text{estimation} \rightarrow \text{valid inference}, p=o(n)→p/n→γ,p=o(n) \rightarrow p/n\rightarrow\gamma, known rank→adaptive unknown rank.\text{known rank} \rightarrow \text{adaptive unknown rank}.
If no substantive distinction survives, do not artificially defend the original claim.
Recommend and implement a stronger research formulation if feasible.

10. Address simulation criticisms by running new experiments
If the review identifies missing simulations, design and execute them.
Do not merely add a sentence saying they are future work if the experiment is important and feasible.
Examples include:
convergence-rate validation;
sample complexity;
contamination curves;
dimension scaling;
rank scaling;
sparsity scaling;
type-I error;
confidence-interval coverage;
power;
assumption violations;
tuning sensitivity;
ablations;
stronger baseline comparisons;
computational scaling.
Each added experiment should correspond to a specific review concern.

11. Test theory directly when requested by the review
If the review says the simulations fail to demonstrate the theorem, explicitly connect them.
For example, if theory predicts
En≍n−α,E_n \asymp n^{-\alpha},
run experiments across nn, estimate
α^,\widehat\alpha,
and compare
α^withα.\widehat\alpha \quad\text{with}\quad \alpha.
If theory predicts
n≳Cslog⁡p,n\gtrsim Cs\log p,
study recovery probability against
nslog⁡p.\frac{n}{s\log p}.
The revised simulations should make the theoretical predictions visible whenever possible.

12. Investigate empirical results that contradict theory
If a reviewer identifies a contradiction between simulations and theoretical claims, investigate rather than explain it away.
Check:
implementation;
parameter regime;
theorem assumptions;
finite-sample constants;
tuning;
numerical optimization;
theoretical derivation.
If the discrepancy remains real, revise the theoretical or empirical claim accordingly.
Do not suppress contradictory results.

13. Strengthen baselines where necessary
If the review identifies weak or missing competitors, add the strongest relevant alternatives.
For each baseline ensure:
proper tuning;
same data splits;
same preprocessing;
comparable information access;
fair computational budget where relevant.
If a stronger baseline substantially reduces the claimed empirical advantage, update the manuscript honestly.

14. Address real-data concerns
For every real-data criticism, determine whether the issue involves:
inappropriate dataset;
insufficient sample size;
data leakage;
incorrect independence assumptions;
improper train/test splitting;
unreported missingness;
weak baseline selection;
insufficient uncertainty;
unsupported interpretation.
Fix the analysis where possible.
If repeated observations exist, identify the true sampling unit.
For example,
Yij=observation j nested within unit iY_{ij} = \text{observation }j \text{ nested within unit }i
should not automatically imply
N=∑imiN=\sum_i m_i
independent observations.

15. If necessary, add a better real-data example
If the review concludes that the current application does not exhibit the phenomenon studied by the theory, identify a better dataset.
Choose it based on the statistical structure, not popularity.
The application should make it possible to observe the practical relevance of the theoretical contribution.
Do not add multiple datasets merely to increase experimental volume.

16. Address computational concerns
If reviewers question computational feasibility, provide:
runtime analysis;
memory complexity;
convergence diagnostics;
scaling experiments.
If theory analyzes an ideal estimator
θ^=arg⁡min⁡θQn(θ)\widehat\theta = \arg\min_\theta Q_n(\theta)
but the implemented procedure returns
θ~,\widetilde\theta,
study whether
Qn(θ~)−Qn(θ^)Q_n(\widetilde\theta)-Q_n(\widehat\theta)
or a comparable optimization error affects the statistical conclusions.

17. Resolve tuning concerns
If reviewers criticize tuning-parameter choices, formalize them.
For example, if theory requires
λ≍σlog⁡pn,\lambda \asymp \sigma \sqrt{\frac{\log p}{n}},
but σ\sigma is unknown, specify how it is estimated.
Compare:
theoretically motivated tuning;
cross-validation;
oracle tuning where useful.
Demonstrate that results are not artifacts of a favorable tuning scheme.

18. Revise claims only after scientific fixes are complete
Do not rewrite the Abstract or Introduction first.
First fix:
Theory→Proofs→Simulations→Real Data\boxed{ \text{Theory} \rightarrow \text{Proofs} \rightarrow \text{Simulations} \rightarrow \text{Real Data} }
Then revise:
Claims→Abstract→Introduction→Discussion\boxed{ \text{Claims} \rightarrow \text{Abstract} \rightarrow \text{Introduction} \rightarrow \text{Discussion} }
The narrative should reflect the final scientific results, not drive them.

19. Revisit every contribution statement
For every contribution bullet in the Introduction, verify:
Is it true?
Is it novel?
Is it supported by a theorem or experiment?
Is it distinct from the other contributions?
Is the wording proportional to the evidence?
Remove or rewrite weak contribution claims.

20. Revise the Abstract only after all results stabilize

21. Strengthen interpretation of the theory
For each theorem, add concise interpretation answering:

Which quantities determine difficulty?
What improves as nn grows?
What deteriorates as p,r,s,ϵ,Tp,r,s,\epsilon,T increase?
How does the result compare with existing theory?
What practical regime does the theorem cover?
The manuscript should not contain technically correct but uninterpreted theory.

27. Do not automatically agree with every review comment
Treat reviewer feedback seriously but critically.
If a requested change is mathematically inappropriate, explain why.
For example, if a reviewer requests a result under assumptions under which the parameter is not identifiable, demonstrate the issue rather than forcing an invalid theorem.
The goal is to improve the science, not mechanically comply with every comment.

Final principle
The objective is not to “address reviewer comments” cosmetically.
The objective is to use the review as an adversarial test of the research and revise the project until the strongest defensible version of the paper remains.
The workflow should be:
Review→Issue diagnosis→Scientific correction→New theory/experiments if required→Manuscript revision→Re-review.\boxed{ \text{Review} \rightarrow \text{Issue diagnosis} \rightarrow \text{Scientific correction} \rightarrow \text{New theory/experiments if required} \rightarrow \text{Manuscript revision} \rightarrow \text{Re-review}. }
Do not weaken scientific standards simply to make every review item appear resolved.
